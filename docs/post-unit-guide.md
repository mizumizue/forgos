# 結合テスト以降（薄いガイド）

単体までの高速ループ（要件〜詳細設計〜開発〜単体）の **外側**。FW はここを強く誘導しない。テスト設計と合否基準の中身は人間が定義する。

## 想定工程

要件定義 → 基本設計 → 詳細設計 → 開発 → 単体 → **（高速ループここまで）** → 結合 → システム → UAT → リリース

## 置き場

| 工程 | 成果物置き場（例） | 備考 |
|------|-------------------|------|
| 結合 | `docs/qa/integration/` | シナリオ一覧・結果メモ |
| システム | `docs/qa/system/` | 非機能・横断確認 |
| UAT | `docs/qa/uat/` | 受入記録（顧客原文は `input/`） |
| リリース | `docs/release/` | チェックリスト・ノート |

ディレクトリは必要になったら作る。空の木を先に増やさない。

## PBI とのリンク

結合以降に進める PBI には次を追記する:

- 結合／システム／UAT の成果物パス
- 再 Verify の要否と実施日
- リリースノートへのリンク（あれば）

## Verify 再実行タイミング（推奨）

- 結合テストで仕様解釈が揺れたとき
- UAT 指摘で仕様変更が入ったとき
- リリース直前（Conform のみでも可）
