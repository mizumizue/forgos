# Scope — run `20260810-lesson-studio`（統合版・工程5）

## テーマ

小規模ピアノ教室における、受講生・定員制グループレッスンの授業枠・出席・振替を、1人講師体制で画面から扱えるようにする。

## 選定理由

前回 run は家計簿（`20260810-kakeibo`）と小規模店舗予約（`20260810-shop-reservation` 系）であった。本テーマは講師と保護者／受講生の **actor-split**、定期授業枠、出席管理、振替ワークフローなど、ForgOS パイプライン実証に適した業務骨格を持つ。予約系とは異なる「継続受講＋枠固定＋欠席対応」の検証軸を追加できる。

## 作業ブランチ

- ブランチ: `validation/20260810-lesson-studio`
- 起点: `main`（コミット `6160aec` から新規作成）

## 通常利用形態

**画面**（Web UI）。講師と保護者／受講生が、主要ユースケースを画面操作だけで完遂する（CLI／API 単独利用は通常形態としない）。

### 主要画面 UC

1. **保護者／受講生 — 在籍枠の確認・期限内欠席連絡・振替希望の申出**（S3 マイ枠）
2. **講師 — 週次レッスン帳での当日出欠確定と定員連動の実施時間記録**（S1 レッスン帳）
3. **講師 — 振替申請キューでの可否判断・同レベル空き枠への確定**（S2 振替キュー）

## システム狙い

ForgOS の正規パイプライン（Source → Promote → map／cut → Implement → Audit）を通し、小規模音楽教室ドメインで **demo-grade** の画面完遂まで実証する。actor-split・定期枠・出席・振替 WF を含む業務アプリとして、工程2–4（sector brief／spec depth／design call）の帰結が辿れる土台を固定する。

## スコープ内（やること）

- 1人講師・定員制グループレッスンを前提とした受講生の登録と在籍状態の扱い
- 曜日・時間で繰り返す定期授業枠（クラス／コース単位）の把握と定員管理
- 各回の出席・欠席の記録と、欠席に伴う振替希望の受付・処理
- 講師面と保護者／受講生面を分けた画面導線（actor-split）
- demo-grade の主要 UC を画面で完遂する正式プロダクト経路上のデモ版

## スコープ外（やらないこと）

- 月謝・決済・請求書発行・口座振替の本実装
- 複数講師・複数教室・チェーン横断のスケジュール統合
- オンライン指導・レッスン動画配信・楽譜販売
- 発表会・コンクール・検定イベントの本格運営（エントリー・会場・審査員割当など）
- 楽器レンタル在庫・販売管理
- SMS／メール／LINE によるリマインド配信の本実装

## sector brief（S0）

**正本:** [`sector-brief.md`](./sector-brief.md)（調査日 2026-08-10）

### 業種

習い事（音楽教育）— ピアノ・鍵盤指導。

### 業態（1つに絞る）

**個人経営・1講師の「定員制集合個人レッスン型」ピアノ教室**（週固定枠・月謝制・定員2〜3名／回）。大手チェーン型・完全個人レッスン型は不採用。

### 顧客属性（≥2）

1. **保護者＋幼児〜小学生** — 送迎・欠席連絡・月謝支払いは保護者が代行。固定曜日枠の把握と期限内連絡を重視（石橋音楽教室 [S1]、KASE [S3]）。
2. **本人申込の中高生・大人** — 自分で欠席連絡・振替相談。固定枠の曜日は学校・仕事と整合（MGS 規約 [S4] は比較参照）。

### 現場オペ（≥2）

1. **OP-1: 固定枠への出欠記録と欠席連絡受付** — 毎週同じ曜日・時間のクラス枠に対し、前日18時等の期限までに欠席連絡を受ける（石橋 [S1]、KASE [S3]）。
2. **OP-2: 振替枠の空き確認と同レベルクラスへの振替手配** — 定員空き・同レベル・再振替不可が通例（石橋 [S1]、ピアノ田中 [S2]）。
3. **OP-4: 欠席によるグループ枠時間の短縮運用** — 1名→20分、2名→45分、3名→60分（田中 [S2]）。

※ OP-3（月謝回収）は brief 通例 T1 として参照するが、`scope.md` §スコープ外のため **在籍維持の状態表示のみ**。

### 差別化しない通例（table stakes・≥3）

1. **月謝＝固定枠の確保料** — 生徒都合欠席でも月謝は原則返金・減額しない（ひらた [S5]、石橋 [S1]）。
2. **振替は定員空き＋同レベル＋期限内有効** — 前日18時／月1回等、教室差はあるが条件分岐が明示される（石橋 [S1]、KASE [S3]）。
3. **グループ単独振替は不可** — 欠席生徒だけの別日個別枠は設けない（ピアノ田中 [S2]、奥井ブログ [S9]）。
4. **欠席連絡は電話・LINE・メール** — 小規模1人講師は LINE が実務チャネル（KASE [S3]、LINE解説 [S7]）。本システムは `ContactChannel` 申告記録のみ。

### 発見→決めの対応表

| 発見（brief） | スコープ上の決め |
|---------------|------------------|
| 固定枠が月謝・出欠・振替の基準（A1） | `WeeklyClassSlot`＋`EnrollmentAssignment` を骨格に採用 |
| 振替は期限・同レベル・定員・再振替不可（A2, T2, T3） | `MakeupRequest` WF と `MakeupPolicyBundle` を採用 |
| 欠席連絡チャネル記録（A3） | `ContactChannel` 申告。配信本実装はスコープ外 |
| 定員連動の実施時間（A4, OP-4） | `RuntimeDurationRule` を採用。S1 で視覚化 |
| 月謝台帳（A5） | スコープ外。在籍状態（active／paused／withdrawn）のみ |
| フリーパス都度予約（D1）・代講（D2）・個別振替枠自動生成（D3） | 見送り |

## actor-split（S2）

役ごとに主表面を分ける。講師は「全クラス・全生徒の編成権」、保護者／受講生は「自子（または本人）の枠のみ」。保護者面に他生徒の氏名・出欠は出さない（空き席数のみ共有）。

| 役 | 主表面 | やること | やらないこと |
|----|--------|----------|--------------|
| **講師** | **S1 レッスン帳（週ストリップ）** | 固定枠の正本・当日出欠・実施時間の確定 | 保護者向け申請フォームの同居、振替確定ボタン（S2 に集約） |
| **講師** | **S2 振替キュー** | 申請の可否判断・同レベル空き枠への確定・override 特例 | 出欠正本の編集（S1 に集約） |
| **保護者／受講生** | **S3 マイ枠** | 在籍枠確認・期限内欠席連絡・振替希望申出 | 他世帯の出欠閲覧、定員超過枠への自己割当、クラス編成変更 |

## surface budget（S3）

主要ハッピーパスの表面は **3**（≤3）:

1. **S1 — 講師レッスン帳（週ストリップ）** — 当日出欠・実施時間確定
2. **S2 — 講師振替キュー** — 振替申請の処理

## demo-seeded（S4）

業態の固定枠・定員段・振替規約が最初から具体値で選べること。汎用の「太郎」「クラスA」だけにしない。

### 教室設定（`MakeupPolicyBundle`）

- **欠席連絡期限:** レッスン前日 18:00（石橋型 [S1]）
- **振替回数:** 月1回（KASE型 [S3]）
- **振替有効期間:** 30日
- **再振替:** 不可（`ReMakeupAllowed=false`、石橋 [S1]）

### 週次クラス枠（`WeeklyClassSlot`）

| 枠名 | 曜日・時刻 | `LevelBand` | `CapacityTier` |
|------|------------|-------------|----------------|
| 初級A・火曜 | 火 16:00 | `BEGINNER_A` | `DUO_45`（2名・45分） |
| 初級A・木曜 | 木 17:00 | `BEGINNER_A` | `TRIO_60`（3名・60分） |
| 3級準備・土曜 | 土 10:00 | `GRADE3_PREP` | `TRIO_60` |

### 実施時間ルール（`RuntimeDurationRule`）

- 出席1名 → 20分、2名 → 45分、3名 → 60分（田中 [S2]）

### 在籍・回次シード

- **在籍生:** 保護者紐づけ児童2名（初級A・火曜）、本人申込中学生1名（3級準備・土曜）
- **今週の回次:** 「予定」1件、「欠席連絡済・振替申請中」1件、「振替確定」1件 — 状態差が S1／S2／S3 で即見える
- **振替キュー:** 申請中カード1件（期限切れ間近バッジ付き）、処理済1件

### 連絡チャネル選択肢

- `WEB_FORM`（デモ既定）／`LINE`／`PHONE` — 申告記録用。配信 UI は作らない

## attention stack（S5）

| 主表面 | 視線優先（先頭＝現場の主タスク） |
|--------|----------------------------------|
| **S1 レッスン帳** | ①今日の縦帯ハイライト列（現在時刻に近いクラス枠）→ ②各枠カード内の座席リング（出席／欠席／未確定）→ ③人数連動の実施時間バッジ。曜日ヘッダ・月謝ドットは従 |
| **S2 振替キュー** | ①期限切れ間近バッジ付き申請カード（残時間昇順）→ ②同レベル空き枠チップ列（タップで確定）→ ③再振替不可／月1回上限の規約ラベル。連絡チャネルは従 |
| **S3 マイ枠** | ①在籍固定枠カード（曜日・時刻・クラス名・レベル帯）→ ②今週の回次ステータス（予定／欠席連絡済／振替確定／振替不可）→ ③主 CTA「欠席を連絡する」／「振替を希望する」（状態で出し分け）。規約全文は折りたたみ |

## 品質 What 候補（S6・≥3）

ピクセル How 禁止。行為・結果の What。

1. 保護者／受講生が期限内に欠席連絡すると、対象回のステータスが「欠席連絡済」となり、講師の S1 当該枠に欠席が反映されること
2. 欠席連絡済の受講生が、同レベル・定員空きの振替先のみを選択して振替申請でき、講師が S2 で確定すると双方の画面に「振替確定」と新日時が反映されること
3. 講師が S1 で各生徒の出欠をトグルすると、出席人数に応じた実施時間（1名20分／2名45分／3名60分）が導出され、確定後に記録がロックされること
4. 振替期限超過・同レベル不一致・定員超過・月間振替回数超過の申請は、講師 override なしでは受理されないこと
5. 保護者面に他受講生の氏名・出欠は表示されず、自世帯（または本人）の枠と状態のみ閲覧できること

## design call（S7・方針）

**正本:** [`design-call.md`](./design-call.md)（2026-08-10）

### 見た目方針（要約）

**ウォームスタジオの「レッスン帳＋座席リング」** を主従にする。講師面は週ストリップ＋今日の縦帯＋定員2〜3の座席リング（G1）と人数連動の実施時間バッジ（G3）。保護者面は在籍固定枠カードと回次ステータス1行。汎用の左サイドバー＋DataTable 管理画面、コールドブルー SaaS スキン、無制限カレンダー CRUD は避ける。ラベルは「レッスン帳」「マイ枠」「振替キュー」（design-call §汎用スキン回避）。

### 遷移方針

- **保護者ホームは常に S3。** 欠席・振替はシート展開→完了後 S3 に戻る。深い階層なし（J1, J2）。
- **講師の振替確定は S2 のみ。** S1 は出欠正本＋振替件数リンク（S2 へアンカー）。S1 に振替確定ボタンは置かない（J4 矛盾チェック）。
- **S1 ↔ S2:** 振替処理完了後「レッスン帳で確認」で振替先週へジャンプ（J4）。
- **期限内のみ CTA 活性。** 期限後はエラー＋「講師に相談」外部リンク。override は S2 講師のみ・確認ダイアログ必須（J2）。
- **ブラウザ戻る:** S3 に戻る（下書き破棄）。各ダイアログに「戻る」あり。

### demo-grade 完了の見え方

保護者 S3 欠席連絡 → 振替申請 → 講師 S2 確定 → 保護者 S3 反映、および講師 S1 座席トグル → 人数連動時間確定、まで画面のみで完遂する。
