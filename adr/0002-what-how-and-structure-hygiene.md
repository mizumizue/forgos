# 決め事は What、How は Impl。構造衛生と Discovery 結晶化を終わり方に入れる

Zenn 記事観点の評価（「始め方ではなく終わらせ方」／Spec=What、How=Impl）を踏まえ、ForgOS が部分整合だった箇所を制度化する。探索→固定・Mode≠Pipeline・TDD／Assure・Order 分離は維持する。

## 文脈

- 定常の「決め事 > コード」は記事の「How の正本は Impl」と緊張しうる。決め事が How・内部構造・手順まで踏み込むと衝突する。
- Impl の入り口削減・責務集約・曖昧分岐の整理（構造衛生）が制度にほぼ無かった。
- Assure の Discovery → Specify 候補はあったが、「終わりの型」として前面化されていなかった。
- 文書レイヤは増やさず、モード完了時の必須コンテキストを絞る方針とする。

## 決定

1. **決め事の射程は What（＋短い Why）**。書いてよい: ドメイン規則、受入／拒否境界、公開インターフェース上の契約、Why。書かない: モジュール分割・配置、アルゴリズム選択、作業手順（Order）、コードを読めば分かる実装詳細。
2. **「決め事 > コード」は What の正本**を意味する。How の正本は `product/`。仕様から実装パスを張らない（憲法 §2.4）は維持。
3. **構造衛生**を L1 工学ライン（E12）と Audit／Implement の終わり方に入れる（入り口数・責務重複・曖昧分岐。振る舞い不変の整理）。
4. **Assure の Promote 候補（Discovery → Specify）**を正規の終わり方として強調する。定常の実装→仕様逆流禁止は維持し、結晶化は Assure／Specify／Promote 経由。
5. **レイヤ追加はしない。** 各モード完了条件で、今必須のコンテキストだけを明示する。
6. Specify 直書き入口は残す。書く／書かない基準で How 混入を抑制する。

## 代替案

| 案 | 却下理由 |
|----|----------|
| 「決め事 > コード」を廃止し How も常に Impl 正 | What の凍結と Audit 可能性が薄れる |
| Specify 入口を廃止し探索必須化 | 小さい変更のコストが過大。ADR-0001 の入口分離と衝突 |
| 構造衛生専用モードを新設 | Mode 増は案内コスト増。Audit／Implement の終わりで足りる |
| 文書レイヤを統合・削減 | 別ラウンド。本 ADR は同期しない情報を完了条件で絞るに留める |

## 決め事への反映

規範の正本は L1（憲法 §2・§7、工学最低ライン E12、Promote ゲート）。案内同期は `CONTEXT.md` / `AGENTS.md` / README、skills（Audit・Implement・Assure・Specify）、Promote テンプレ／リファレンス。製品ドメイン決め事は変更しない。
