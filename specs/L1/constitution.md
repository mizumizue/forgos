# L1 憲法（メタ原則）

Agent は本ディレクトリを **Maintain-FW フロー経由以外で編集しない**。変更は人間承認後に版を上げる。

## 1. プロダクトの形

1. 本リポジトリは **リポジトリ規約** と **AI 工程 OS（Cursor 第一）** を一体にしたスターターである。
2. コア規約は特定アプリスタックに依存しない。参考実装は `examples/` に置く。
3. プロダクト実装（`apps` / `infra` / `sandbox`）は `product/` 配下に置き、リポジトリルートは工程・知識用とする。
4. インフラはアプリと同体系・別ドメインとして扱い、`specs/L3/infrastructure/` と `product/infra/` に隔離する。

## 2. 正本の順位

1. **Explore** 中: 仮の正は sandbox 実装。仕様は後でよい。
2. **Extract 後〜定常**: **決め事（仕様）> ADR > コード**。PBI は要求・進捗・リンクのハブであり正本にしない。
3. **Spec-only**: 仕様（＋必要なら ADR/PBI）のみで完了してよい。
4. ADR は意思決定の経緯（代替案・却下理由）。規範の正本ではない。規範は決め事に書く。

## 3. 仕様レイヤ

| レイヤ | 内容 | Agent 編集 |
|--------|------|------------|
| L1 | FW 絶対原則＋工学最低ライン | 不可（Maintain-FW のみ） |
| L2 | プロダクト横断仕様 | 成熟度ルールに従う |
| L3 | ドメイン別（`infrastructure/` 含む） | 成熟度ルールに従う |

各レイヤ／ドメインは **用語 / アクター / 決め事** の 3 種に分ける。

## 4. 成熟度

| 成熟度 | Agent の仕様編集 | 実装 |
|--------|------------------|------|
| draft | 可（提案・抽出） | 探索のみ（通常 feature に紐づけない） |
| stable | 可（差分明示） | 通常開発可（Build の前提） |
| confirmed | 原則不可（変更提案→人間承認、必要なら降格） | 確定仕様に従う実装可 |

実装ルール:

- 探索コードは仕様未紐づけ、または draft 明示の **sandbox**
- 通常 feature 実装は **stable 以上** の決め事にのみ紐づける

## 5. Extract ゲート

仕様昇格は **人間との対話による抽出** がゲートである。自動昇格しない。詳細は [extract-gate.md](./extract-gate.md)。

## 6. 作業モード（公式 5）

Explore / Build / Spec-only / Maintain-FW / Verify。Extract は独立モードにしない。詳細は `docs/modes.md`。

## 7. Build と TDD

1. Build モードでは **TDD 必須**（red → green → refactor）。
2. テストなき Build 完了を認めない。
3. インフラはクラシック TDD ではなく、先出し検証（policy / plan / 契約テスト等）を用いる。

## 8. 人間レビュー

人間はコードレビューしない。レビュー対象は **仕様意図** と **既存仕様との整合**。

## 9. PBI

1. 単位はユーザー価値の一塊。大きいテーマは任意で薄い Epic。
2. `done` 条件と `specified`（仕様のみ完了）を混同しない。定義は `docs/pbl.md`。
3. 必須リンク: 受入条件 or 参照決め事、関連仕様パス、関連コード/PR、状態。

## 10. インプット

`input/` はローカルのみ（git 管理しない）。抽出結果だけを `specs/` / `pbl/` / `adr/` へ載せる。

## 11. 結合以降

結合〜UAT〜リリースは高速ループの外。置き場と薄いガイド（`docs/post-unit-guide.md`）のみ提供し、強く誘導しない。
